Placement detail: WPF positions a window in device-independent units of the monitor it is currently on, so the physical target is divided by the window's current scale, with a 0.25 px nudge away from zero so rounding or truncation inside WPF cannot move it by a pixel (also for negative coordinates). After the window changes monitor, WPF's `DpiChanged` triggers one more placement with the new scale. Debug log events (`island.display.changed`, `island.window.dpi.changed`, `island.position.applied`, no values) show which trigger fired; failures log `island.position.fallback` / `island.position.listener.failed` with an error code.

- The two `applied` lines come about a second after the notifications, so the move is not instant while Windows is changing the scale (not measured further).
