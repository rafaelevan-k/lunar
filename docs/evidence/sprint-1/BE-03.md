## Implemented

All types are in `Lunar.Domain.Shared`, BCL only.

| File | Content |
|---|---|
| `src/Lunar.Domain/Shared/ErrorCode.cs` | `ErrorCode`: the nine categories listed in ARCHITECTURE §6 |
| `src/Lunar.Domain/Shared/OperationError.cs` | Immutable `OperationError(Code, SafeMessage, Retryable)`; rejects undefined codes and blank messages; `OperationError.Cancelled()` |
| `src/Lunar.Domain/Shared/Result.cs` | `Result` and `Result<T>`: `IsSuccess`/`IsFailure`/`IsCancelled`, `Error`, `Value` (throws on failure), `TryGetValue`, `Map`, `Match`, `ToResult`; static factories `Success`, `Failure`, `Cancelled` |

Semantics:
- Expected failures are returned as typed errors; unexpected faults stay exceptions.
- Cancellation is a failure with `ErrorCode.Cancelled`, never retryable. Adapters/use cases convert `OperationCanceledException` at their boundary; the Domain does not catch it.
- A failure always carries a non-null error, so a success can never look like a failure or the reverse.
- `SafeMessage` is documented as free of paths, content, SSIDs, titles, credentials and raw exception text. The type cannot enforce this; callers and BE-07 redaction remain responsible.
- `OperationResult` from the illustrative ARCHITECTURE §6 sketch is not added; `Result` replaces it. Exact port signatures remain BE-04 work.

Tests: `tests/Lunar.Domain.Tests/Shared/OperationErrorTests.cs`, `ResultTests.cs` (19 new tests: success, failure, null error, cancellation, undefined code, blank message, value access, `Map` without invoking the mapper on failure, `Match`, nullable success value).
