## Implemented

`Lunar.Application` (no package, references Domain only):
- Ports in `Abstractions/System`: `IVolumeService`, `IWifiService`, `IBluetoothService`, `IClock`, `ISystemSettingsLauncher`, enum `SettingsPage` (whitelist). `Abstractions/Media`: `IMediaService`.
- Models in `System/Models`: `CapabilityStatus`, `RadioState`, `WifiConnectivity`, `VolumeState` (validated 0..1), `WifiState`, `BluetoothState`. `Media/Models`: `MediaPlaybackStatus`, `MediaCapabilities`, `MediaSessionSnapshot` (validated; artwork at most 2 MiB; `CanSeek` needs a finite duration plus capability).
- Reads return `Task<Result<T>>`, commands `Task<Result>`; cancellation is a failed `Result`. Observable semantics are documented on `IVolumeService.Changes` and referenced by the other ports.

`Lunar.Desktop`: `Composition/ServiceRegistration.BuildServiceProvider(configure)` builds a container with `ValidateScopes` and `ValidateOnBuild`. Nothing is registered by default because no adapter exists yet; adapters are registered by the tasks that create them. Package added: `Microsoft.Extensions.DependencyInjection` 10.0.13, Desktop only.

Tests:
- `Lunar.Application.Tests`: reusable fakes (`Fakes/`: `TestObservable<T>`, volume, Wi-Fi, Bluetooth, media, clock, settings launcher), `ModelValidationTests`, `PortContractTests`.
- `Lunar.Desktop.UITests/Composition/ServiceRegistrationTests.cs`: 6 container tests. They test DI behavior only, no UI; two fake files are linked from the Application tests.
