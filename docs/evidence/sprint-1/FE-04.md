## Scoping decision (read this first)

BE_TASK BE-09 (Sprint 2–3, `Lunar.Application/Shell`) owns "validated state transitions and events, interruption/reentrancy rules and time abstraction". FE-04 (Sprint 1) needs deterministic transitions now. To avoid pre-empting BE-09 or creating an Application contract without an ADR, FE-04 defines only a **presentation** enum in Desktop and the smallest transition set:
- Idle → Expanding (toggle); Expanded/Busy → Collapsing (toggle or collapse); animation completion is reported by the view (`CompleteExpansion`, `CompleteCollapse`), so the view model owns no timer and is a pure function of state and request.
- A request that does not apply (including any request while an animation runs) is ignored and returns false. Interrupting an animation, guards (dialog, drag, focus), the 300 ms debounce and time belong to BE-09.
- Busy is the Expanded state while a background job is active; the flag survives a collapse ("job continues after collapse"), so an idle island can be busy.
- Errors are an inline message (`OperationError.SafeMessage`) that never changes the state.
When BE-09 lands, its use case replaces the transition logic here; the bindings stay.
