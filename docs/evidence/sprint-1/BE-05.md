## Acceptance

| Criterion | Evidence |
|---|---|
| Second launch activates first | The request is delivered and the primary's handler runs: unit tests prove exactly one `ActivationRequested` per valid request, repeated requests, and survival after a bad byte, a silent client and a throwing handler. In the real exe the pill took the foreground after the second launch in run 1 and **did not** in the final run, so whether Windows lets a background-launched process pull foreground is not reliable; the activation itself equals tray Open and is best-effort for foreground (as ADR-0008 anticipated). |
| Clean process exit | `WM_CLOSE` exit code 0 with no leftover process, three times; tray Exit proved manually in FE-06; the second launch always exits 0/3/1 without lingering |

Manual Windows verification: PARTIAL — scripted two-process smoke only; no RDP, fast-user-switching or second logged-on user.

## Limitations

- Foreground on activation is not guaranteed (above). A reliable approach would have the secondary call `AllowSetForegroundWindow` for the primary's process id, which needs a reply channel and an ADR amendment; not done.
- Scope is per Windows session; same-session processes can block startup by pre-creating the name (local denial of service only).
- Start failure and startup exceptions recorded only the exception type via `Trace` at the time of BE-05. **Updated by BE-07 the same day:** they now go to the structured diagnostic log (`Trace` remains only before the log exists). A second launch that finds an unreachable primary still exits silently with code 3 (now logged as `instance.activation.failed`); no user-visible message is planned yet.
- `async void OnStartup` is the only async-void use and is wrapped in try/catch.
- No handling of `DispatcherUnhandledException` yet (BE-07/robustness).
- Tray Exit now calls the same `Shutdown` path; "graceful settle of in-flight operations" has nothing to settle yet because no long-running work exists.
- FE-06's duplicate-icon limitation is resolved for same-session launches; verified by process count and window count, not by looking at the tray.
