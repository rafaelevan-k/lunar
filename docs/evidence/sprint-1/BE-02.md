## Findings kept visible

1. **Intermittent UI test failure (real, pre-existing since FE-03/FE-04).** The first `-Suite Hardware` run failed in `Lunar.Desktop.UITests` and passed on rerun. Repeating the suite reproduced it: about 4 failures in 25 and 4 in 30 runs, always a `XamlParseException` / `KeyNotFoundException` ("The given key 'Mode' ... 'Title' ... was not present in the dictionary") or an index error while constructing `IslandWindow`. Cause: tests on different STA threads parse XAML at the same time, which WPF's XAML loader does not support. The earlier "three extra runs passed" for FE-03/FE-04 were luck. Fix: disable test parallelization for that assembly (`[assembly: Parallelization(Mode = ParallelMode.None)]`); 0 failures in 40 consecutive runs afterwards. The production app loads XAML on one thread and is not affected. My first two attempts at the attribute did not compile (an obsolete property, then a wrong namespace); during those, the repeat runs still used the old binary, which is why they kept failing.
2. A first clean-clone run failed only because I cloned into a deeply nested scratch path and xUnit could not start the test executable (path longer than 260 characters). The repository is fine; the clone was redone at a short path. CI workspaces are short.
3. The gate's first negative test failed to build because my mutation was a compile error; a build error also blocks, but the case was redone with a mutation that compiles and fails at run time.
